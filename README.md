# project-maven-ro
รายการนี้สรุปจากบทสนทนาที่มีอยู่ ยังไม่ได้ตรวจซอร์สหรือสถานะติดตั้งบนเครื่อง งานเก่าที่ไม่ยืนยันผลให้ตรวจสถานะก่อนเริ่มซ้ำ ลำดับหลัง RO Studio เป็นข้อเสนอ ยังไม่ได้กำหนดวันส่งมอบ

1. งานหลักที่ยืนยันแล้ว

☐ RO Studio: ความเร็ว ความถูกต้อง และลดอาการค้าง — สำคัญอันดับแรก
  • ตรวจซอร์สเวอร์ชันล่าสุดและวัดเวลาเปิดไฟล์/ค้นหา/แสดงรูปก่อนแก้
  • รองรับ GRF และฐานข้อมูลขนาดใหญ่ แสดงรายการครบ
  • ตรวจลำดับโหลดไฟล์ของ Client จริง และการเชื่อม Item ID → itemInfo → Resource → รูปภาพ
  • แสดงที่มาของรูปและสาเหตุเมื่อหาไฟล์ไม่พบ ตรวจ encoding
  • ย้ายงานหนักออกจากส่วนแสดงผล เพิ่มความคืบหน้าและยกเลิกงาน
  • จัดการแคช งานโหลดซ้ำ และการใช้หน่วยความจำ
  • ทดสอบเทียบกับในเกม รวมไอเทม Custom; กรณีเดิมที่เคยรายงานคือ Item ID 54000 ต้องตรวจว่ายังเกิดอยู่หรือไม่
  • เกณฑ์ผ่าน: ข้อมูลครบ รูปตรงกับ Client ชุดทดสอบ หน้าจอยังตอบสนองระหว่างโหลด และมีผลวัดก่อน–หลัง
  • สิ่งที่ต้องใช้: ซอร์สล่าสุด โฟลเดอร์ Client ที่ใช้จริง และชุดข้อมูลทดสอบ
☐ Hot Week Shop: ร้านไอเทมลิมิเต็ด — รอตรวจงานล่าสุดและทดสอบต่อ
  • ตั้งวันและเวลาเปิด–ปิด
  • จำกัดจำนวนขาย โดย 0 = ไม่จำกัด
  • รูปแบบ Barter Shop V2 พร้อมกำหนดโอกาสสำเร็จ
  • ตรวจการหักวัตถุดิบ การให้รางวัล สต็อก และการรับคำขอซ้ำ ป้องกันไอเทมซ้ำ/ความคลาดเคลื่อนเมื่อเกิดข้อผิดพลาด
  • มีประวัติสร้างไฟล์ชื่อ MAVEN_Hot_Week_Shop_DRAFT.zip แต่ยังไม่ได้เปิดตรวจเนื้อหาในรอบนี้ จึงยังไม่รับรองความพร้อมใช้งาน
  • ต้องกำหนดเพิ่ม: ของที่ขาย ราคา โอกาสสำเร็จ สต็อกรวม/ต่อบัญชี และวิธีนับสต็อกเมื่อแลกไม่สำเร็จ

2. แนวคิดล่าสุด รอเลือกกติกา

☐ Attendance / Daily Login Reward
  • ตรวจความเข้ากันได้ของ Client 2025, Source และไฟล์ Attendance
  • ออกแบบรางวัลรายวันและรางวัลสะสม
  • ข้อเสนอของผู้ช่วยที่ยังไม่ได้ยืนยัน: สะสม 20 วันในรอบ 28 วัน, รับวันละครั้งต่อบัญชี, ขาดวันไม่ล้างความคืบหน้า, เปลี่ยนวัน 00:00 เวลาไทย
  • ตัวเลือกรางวัล: ของใช้ เหรียญเช็กอิน ร้านแลกของ และ Costume ประจำรอบ
  • ยังไม่ยืนยันเพิ่มเงื่อนไขออนไลน์ครบเวลา/รางวัล VIP/รางวัลผู้เล่นกลับมา
☐ Attendance Editor ใน RO Studio — ข้อเสนอต่อยอดของผู้ช่วย
  • จัดรางวัลแบบปฏิทิน แสดงรูป ตรวจ Item ID และสร้างไฟล์ Server/Client ให้ตรงกัน
  • ทำภายหลังงานเสถียรภาพ หากผู้ใช้เลือกพัฒนาต่อ

3. แนวคิดจากบทสนทนาก่อนหน้า — ยังไม่กำหนดคิว และต้องยืนยันสถานะล่าสุด

|แผน                 |เป้าหมาย / สถานะที่ทราบ                                               |

|พัฒนา Autoattack     |เพิ่มความเสถียรและปรับระบบให้ทันสมัย; ต้องตรวจ implementation ล่าสุดก่อนวางงาน|

|Battle Pass         |เคยสนใจแนวทาง ยังไม่เลือกภารกิจ รอบกิจกรรม และรางวัล                     |

4. พักไว้ตามบทสนทนาก่อนหน้า

• เติมเงินผ่าน NPC — ผู้ใช้ระบุค่อยว่ากัน ยังไม่เริ่มรอบใหม่
• roBrowser / เล่นผ่านเว็บ — พักไว้เพื่อทำ Client ให้เสถียรก่อน

วิธีอัปเดตรายการ

• สถานะงาน: รอทำ → กำลังทำ → รอทดสอบในเกม → เสร็จแล้ว
• งานถือว่าเสร็จเมื่อมีผลตรวจตามเป้าหมาย ไม่ใช่เพียงสร้างไฟล์แล้ว
• บันทึกเวอร์ชัน ผลทดสอบ และงานคงเหลือเมื่อเริ่มทำแต่ละรายการ
• ไม่รวมงาน NPC/Console เก่าทั้งหมดเป็นงานค้างโดยอัตโนมัติ เพราะหลายรายการมีการแก้ไขหรือยกเลิกไปแล้ว
